# 요구사항 정의 (MVP, 2026-09)

## 1. 목표
소모 주기가 일정한 생활필수품을 사용자가 정한 주기로 자동 주문·결제·배송한다. 사용자는 상품·주기·수량만 정하고, 서비스가 결제일 하루 전 알림 → 자동 결제 → 주문 생성을 수행한다. 사용자는 언제든 건너뛰기·일시정지·주기 변경·해지할 수 있다.

## 2. 사용자 유형
| 유형 | 설명 |
|---|---|
| 회원(USER) | 상품 탐색, 구독 생성·관리, 결제 수단 등록 |
| 관리자(ADMIN) | 상품·주문·구독 현황 관리, 결제 실패 대응 |
| 시스템(스케줄러) | 매일 09:00 결제 예정 구독을 조회해 자동 결제·주문 생성·알림 |

## 3. 기능 요구사항 (사용자 스토리 · 수용 기준)

### F0. 인증
- US-01 회원은 이메일·비밀번호로 가입하고 로그인할 수 있다.
  - AC: 비밀번호는 bcrypt 해시로만 저장한다. 중복 이메일은 409를 반환한다.
  - AC: 로그인 성공 시 액세스(15분)·리프레시(14일) 토큰을 httpOnly 쿠키로 발급한다.
  - AC: 리프레시 토큰은 회전(rotate)되며 로그아웃 시 폐기된다.
- US-02 회원은 카카오·구글 계정으로 로그인할 수 있다.
  - AC: OAuth 2.0 인가 코드 방식으로 API 서버가 토큰을 교환한다.
  - AC: 같은 이메일의 기존 계정이 있으면 해당 계정에 소셜 계정을 연결한다.

### F1. 상품 탐색·검색
- US-03 회원은 카테고리(세제·화장지·생수·커피·주방·반려용품)별 상품 목록을 본다.
  - AC: 목록·상세는 SSR로 렌더링되고 정가·구독가(5% 할인)·추천 주기를 표시한다.
- US-04 회원은 키워드로 상품을 검색할 수 있다.
  - AC: 상품명·설명에 대한 부분 일치 검색, 결과 없음 상태를 표시한다.

### F2. 구독 생성
- US-05 회원은 상품에 대해 수량·배송 주기(2·4·6·8주 또는 직접 입력 7~90일)·첫 배송일을 정해 구독을 만든다.
  - AC: 회당 결제 금액과 다음 결제일(첫 배송일 3일 전)을 생성 전에 보여준다.
  - AC: 결제 수단이 없으면 구독은 PENDING 상태로 생성되고 카드 등록을 안내한다.

### F3. 구독 관리
- US-06 회원은 마이페이지에서 구독별 상태·다음 결제일·배송일을 본다.
- US-07 회원은 이번 회차 건너뛰기, 일시정지·재개, 주기·수량 변경, 해지를 할 수 있다.
  - AC: 허용된 상태 전이만 실행된다([state-machine.md](state-machine.md)).
  - AC: 건너뛰기는 다음 결제일을 한 주기 뒤로 미룬다. 변경 결과가 즉시 화면에 반영된다.
- US-08 회원은 이번 달 예정 결제 금액 합계를 마이페이지 상단에서 본다.

### F4. 빌링키 자동 정기결제
- US-09 회원은 토스페이먼츠 카드 등록창으로 카드를 한 번 등록한다.
  - AC: 서버는 카드 번호를 저장하지 않고 빌링키만 AES-256으로 암호화해 보관한다.
- US-10 시스템은 매일 09:00 결제 예정(nextBillingDate ≤ 오늘, ACTIVE) 구독을 자동 결제한다.
  - AC: orderKey = `sub_{구독ID}_{YYYYMMDD}` 멱등키로 같은 회차 중복 결제를 막는다.
  - AC: 승인·주문 생성·다음 결제일 갱신은 하나의 트랜잭션이다.
  - AC: 실패 시 PAYMENT_FAILED로 전환, 1일 후 재시도, 3회 연속 실패 시 자동 해지.

### F5. 알림
- US-11 회원은 결제 D-1, 결제 완료·실패, 배송 출발 이메일을 받는다.
  - AC: 알림 이력(Notification)이 저장되고 같은 회차에 중복 발송되지 않는다.

### F6. 관리자
- US-12 관리자는 활성 구독 수, 오늘 결제 예정, 결제 실패, 월 구독 매출을 대시보드에서 본다.
- US-13 관리자는 상품 등록·수정·품절 처리, 주문 배송 상태 변경, 구독 현황 조회를 할 수 있다.
  - AC: ADMIN 역할만 접근 가능(403).

## 4. MVP 범위
| 포함 | 제외(향후) |
|---|---|
| 자체 가입·로그인, 카카오·구글 로그인 | 네이버·애플 로그인, 휴대폰 본인인증 |
| 상품 목록·검색·상세, 장바구니 | 리뷰·평점, 추천 알고리즘 |
| 구독 생성·건너뛰기·일시정지·주기 변경·해지 | 합배송 최적화 |
| 토스 빌링키 등록·자동 결제·재시도 (테스트 키) | 실 결제 계약, 네이버페이·카카오페이 |
| 이메일 알림 | 알림톡·앱 푸시 |
| 관리자 대시보드·상품·주문·구독 관리 | 택배사 연동(배송 상태는 수동 갱신) |

## 5. 비기능 요구사항
- HTTPS 필수(소셜 로그인 리다이렉트·토스 결제창 요건). 운영은 Nginx + Let's Encrypt.
- 상품 목록 SSR 응답 1초 이내, Lighthouse 모바일 성능 80점 이상.
- 모바일(360~430px) 우선 반응형, 태블릿·PC 확장.
- 비밀 값은 환경 변수로만 관리. 카드 번호 미보관.
- 단위 테스트 커버리지(구독·결제 도메인) 70% 이상, E2E 시나리오 5개.

## 6. 용어
- 주기(cycleDays): 배송 간격(일). 결제일은 배송일 3일 전.
- 회차: 한 번의 결제·주문·배송 단위.
- 빌링키: 토스페이먼츠가 카드 인증 후 발급하는 자동결제용 키.
